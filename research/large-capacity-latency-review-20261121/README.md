## What the previous evidence establishes

The September FPGA probe reports a **41-cycle median dependent load/use window**, range 41–44 over 48 first-touch samples, with a three-cycle cached/timer control. Its frozen source executes CSR/LD/dependent-ADDI/CSR. It does not timestamp AXI AR, first response, or full-line completion; the old physical path also differs from the current full-burst topology. Its accepted quiet simulator audit explicitly shows early load completion before the complete ordinary line refill. Therefore neither 41 nor 41 minus three is a calibrated full-line prefetch response or HP0 memory latency. The historical 21–25-cycle detached-path observation is likewise not a current full64B calibration. Exact old source, accepted summary and explanation are bound in `bindings.json`.

The closed controls use the same F35 ELF (`f35e5da8…93dd`), patched NBF (`18dbba12…103d`), two resident slots/four logical contexts, fixed 32KiB private lookup corpus, capture off, full 64-bit burst transport, memory read queue four, and one L2 bank. The physical reference and intended new primary keep two L2 banks. Model identities are `77f76ae7…4ad5` at 40 and `e52fa247…0c3f` at 200. All 6,508 normal D misses pair with 6,508 complete refills/52,064 accepted beats in both executions. The timed 1,711 misses have accepted-D-miss→first accepted D-fill medians 61/221 and full-fill medians 69/229; complete timed ring costs are 431,132/705,445 core-global cycles. These are controlled synthetic results, not Linux or FPGA results. The first accepted D-fill beat may not contain the requested critical word. Pending occupancy is not CPU stall time or an exclusive causal partition. No repeat of this control is needed to rediscover first-response sensitivity.

## Actual path and surviving provenance

| L2 DMA→`cache2axi` | DMA supplies bank/address/write flag; original I/D/prefetch identity is absent from the DMA packet. Private bank-order FIFO routes normal replies. | Off-chip bank/order known internally; original source cannot be inferred from HP0 ID alone. |
| HP0 | Normal ARID0; 64-bit data, 64B read gives ARLEN7/ARSIZE3/INCR. RLAST and RRESP survive at HP0, though the normal RX consumes a fixed eight-beat count and does not use RID/RLAST for routing. | AR acceptance→first offered R, first accepted R, accepted RLAST, per-beat gaps, backpressure and actual outstanding depth. |

The external top sets core and AXI to the same `aclk`, asynchronous mode0, default design target20MHz. HP0 remaps guest DRAM by `(guest_addr XOR 0x80000000) + dram_base`; it is not an ownership mask. Existing 46MiB allocation/mem-bound checks remain necessary. GP/HP1 I/O is outside the DDR HP0 path. I and D UCEs run opposite phases; local SRAM-service timestamps must retain edge/phase alignment rather than assuming an unproved cycle offset. The closed full-burst AXI audit verifies its BE/AXI clock identity, not an independently measured physical oscillator frequency.

`BP_PREFETCH_AXI_BYPASS` is **absent** in the intended primary; the top's implicit bypass selection applies only to named five-/ten-context endpoints, not `prefetch16k`. If explicitly enabled later, only detached **D** prefetch bypasses L2. Its bridge uses nonzero RID (slot+1), buffers the whole AXI line before emitting BedRock, and the top limits it to one outstanding slot. Normal I/D and I prefetch still share RID0 through L2. Consequently first UCE data on the bypass path can occur only after full AXI arrival; it is not first HP0 response. Changing this topology would require a separate matched study.

The normal bridge's read-tag FIFO defaults to `num_cce*l2_dmas`, with `l2_dmas=l2_slices*l2_banks`: one outstanding normal AXI read in the closed one-bank models and an upper bound of two in the intended two-bank primary. Each blocking L2 bank has one miss handler. Four UCE hint slots per side do not imply eight simultaneous DRAM reads. An explicitly enabled one-slot D bypass could add one, but is not primary. Peak unblocked HP0 transfer is one64-bit beat/core cycle, eight beats per line; at the uncalibrated20MHz target this is160MB/s. Actual admission, burst gaps, contention, PS traffic and backpressure can reduce it. The board manual's16-bit DDR3 at1050Mb/s describes a2.1GB/s pin-rate ceiling, not delivered HP0 throughput or measured board settings. [TUL PYNQ-Z2 reference manual, pp.4/10](https://pynq.tue.nl/doc/pynqz2_user_manual_v1_0.pdf).

## Minimal decisive calibration, before a sweep

Use one checked bare-metal ELF with warm measurement code, first-touch code/data regions, fixed deterministic permutations, and no print/storage inside measurement windows. Do not tune a replay table or a favorable address subset. Record the exact ELF/NBF/bitstream, actual allocation/mapping/clock configuration and all samples, including failures.

1. A passive HP0 monitor timestamps **ARVALID&&ARREADY** and maintains a bounded per-RID FIFO (RID0 may have several requests). For every burst retain address, ARLEN, ARSIZE, ID, first RVALID offer, first RVALID&&RREADY, every accepted beat count, accepted RLAST and response errors. Record separate accepted/offer counts, unmatched/overflow/length-error flags, outstanding high-water, AR/R stalls, and intra-burst gaps. Freeze a small BRAM trace on completion; overflow/unmatched/error means failed calibration. Same-ID requests pair in issue order; never pair only by address. B-channel monitoring similarly records AW/WLAST/B offer/accept, without calling B receipt DRAM write latency alone.
2. Add small source-local UCE records for accepted ordinary I/D request, accepted outgoing prefetch, first/critical/full accepted refill, retained-hit outcome and completed retained publication. Preserve physical address, request sequence and class, plus clock phase/offset. A backend publication after eight BRAM writes is a different endpoint from final UCE/AXI data. If arbitrary-traffic per-class HP0 attribution is needed, carry monitor-only source tags through the L2 miss→bank/DMA association; source information is already lost at the bare DMA/HP0 boundary.
3. Cheapest initial classification uses **serialized labeled windows** with one outstanding cold request and a terminal drain checked by the monitor. D windows use distinct64B lines and a checked dependent load; I windows jump once into fresh aligned register-only code lines and check their result; I-/D-prefetch windows use the existing respective hint ingress on fresh code/data lines. A warm harness and source-local records verify that unrelated accesses did not contaminate the window. L2 hits must be reported separately rather than called cold DRAM. Check all eight data words/code result outside timing, then repeat cached controls. `fence.i` alone does not flush L2 or prove DRAM coldness.
4. After single-request endpoint/clock validation, a short fixed two-bank/both-side overlap control checks that native0 versus +N shifts first/full response without an extra inter-beat bubble or unintended admission serialization. This is a transport correctness check, not a new performance winner search. Keep actual queue/backpressure changes visible.

A common HP0 R+B delay belongs **before response demultiplexing**, with all IDs and errors carried intact, and identical configuration in baseline/I-only/D-only/joint arms. Native0 must be a true bypass. For +N, timestamp both native PS arrival and delayed release; report first/full input→output shifts, queue occupancy and full-input stalls. Preserve accepted ownership across clear/disable and change N only under proved AR/AW/response quiescence. A finite FIFO preserves one-beat throughput only while not saturated; increased credit occupancy and any resulting contention are real complete-execution costs. Delaying B also extends writeback/ordering ownership, so omitting its cost would bias results. HP0 injection delays off-chip traffic; L2/retained hits and non-DDR I/O legitimately avoid it. AMD documents that read flow may contain gaps/interleaving and B timing depends on competing traffic, so a constant chip-latency interpretation is inappropriate. [AMD UG585 HP performance notes](https://docs.amd.com/r/en-US/ug585-zynq-7000-SoC-TRM/Performance-Optimization-Summary).

## Plausible cycles, not an FPGA calibration

Lenovo's own Multichase measurements report average local-node dependent memory latency76–82ns for EPYC Gen3 and90–103ns for Gen2. These CPU-visible values include more than bare DRAM command timing. [Lenovo LP1492, Tables1/2](https://lenovopress.lenovo.com/lp1492-configuring-memory-speed-for-optimal-memory-latency-amd-epyc). A primary DRAM study independently uses a3.2GHz processor/64B lines and DDR3 in simulation, and distinguishes DRAM timing parameters from system performance. [DIVA-DRAM, Table1/§4](https://people.inf.ethz.ch/omutlu/pub/DIVA-low-latency-DRAM_sigmetrics17-paper.pdf).

| Assumed future CPU frequency |76–103ns expressed as CPU cycles (ceil) |
|---|---:|
|1GHz |76–103|
|2GHz |152–206|
|3.2GHz |244–330|

These arithmetic scenarios justify studying roughly100–330 total CPU-visible miss cycles, with a larger384-cycle sensitivity margin; they do not establish a BlackParrot ASIC frequency or an HP0 target latency. The injection parameter **N is additional response delay**, not that total. Never calculate it by subtracting the old41-cycle load/use number from a desired AR/full-line latency. First calibrate like-for-like endpoints at native0, then report both native and native+N distributions; a candidate total cannot be reached with positive delay if native latency already exceeds it. A small fixed N grid such as0/64/128/256/384 is a proposal, not an acquired or preregistered result.

At20MHz, +384 physically adds19.2microseconds; viewed at an assumed3.2GHz it represents120ns of additional CPU-cycle delay. Preserving8B/core-cycle transport would correspond to8/16/25.6GB/s at hypothetical1/2/3.2GHz, so latency injection alone is not a calibrated future memory system. Report conditional cycle sensitivity and complete application costs separately from actual FPGA wall time and measured native FPGA service.
