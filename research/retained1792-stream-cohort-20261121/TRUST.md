This review separates internal file consistency from trusted provenance in the generic archival helper. The closed64D/1280D qualification used known accepted inputs and exact sources; it remains valid. The issues below concern future adoption of an unanchored external package.

`archive_stream.check_chain(out)` accepts an `acceptance.json` whose file, source and input paths and digests are supplied by that same unsigned file. It has no independently supplied acceptance digest, fixed expected source set, model/role/program/native identity, or owned-path contract. A self-consistent replacement graph could therefore redirect inputs, supply a different original semantic proof, and fabricate a checker receipt while updating its hashes. It also checks checker relationships without itself requiring the exact expected checker state and six values. Hash consistency alone does not authenticate an execution.

The new contract requires a trusted preparation SHA before reading its declared graph, an externally captured native-proof SHA before auditing, and the actual prior-audit acceptance SHAs before advancing to the next case. It checks the exact runtime source map and content-pins imported foundation modules before import. The audit verifier derives every artifact path from the approved stage and role; it checks the exact rawFST, full167 schema, model/software/reader provenance, adapter relationship, unchanged checker source, PASS state and all six values, plus actual owned-reader/checker completion. Self-declared paths outside that fixed file set fail even if their individual hashes are valid.

The SHA anchors must come from root-observed closed phases under the reviewed driver and owned stage. Computing a hash from an unreviewed package and calling it approved does not establish provenance. This is a source-bound research workflow, not a signature or protection against an adversary controlling the executing host. The original generic helper and its sealed qualification are preserved; the new verifier does not relax or bypass the frozen old cohort gate.

Pending-draft review checks local bundle bytes independently of a relocated checkout path. Execution approval always requires the exact runtime paths and source records; relocation requires a fresh admission, not rebasing an accepted proof.
