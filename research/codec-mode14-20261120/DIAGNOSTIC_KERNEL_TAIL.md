This is a **diagnostic-only host observation extension**, excluded from performance inference even if a run happens to complete. It does not resume the stopped codec coordinator, retry the performance cohort, change target flags or establish a failure cause. The coordinator must separately preregister the one intended exact A1 diagnostic before any board launch; this implementation task launches no board/model/ELF.

`diagnostic_kernel_tail.py` imports the unchanged session wrapper and guest runner. Its subclass intercepts only a successful synchronous `expect_list` match whose selected compiled pattern object **is the unchanged `KERNEL_FAILURE_MARKER`**. It permits one original-engine `expect_list([EOF,TIMEOUT], timeout=20)` per spawn, allowing extra UART text to enter the existing `logfile_read` stream before ordinary shutdown. EOF, timeout and read errors all preserve the original failure outcome. A `finally` block restores the original `before`, `after`, exact `match` object and `match_index`; the original guard therefore still raises its kernel-failure error and writes FAIL. Cancellation propagates after restoring those fields. The extension sends no console command and does not bypass a guard.

All staging, global flock, board-side program lock, fresh recovery, ordinary failure status and recovery remain owned by unchanged `run_resume_workload_session.main`. The spawn substitution exists only in this diagnostic process and is restored afterward. Source8, board helper, ELF/library/images and the stopped external coordinator/gate/launcher files are untouched. A no-trigger PASS returns through the unchanged delegate; it is still **diagnostic, not an admitted performance sample**.

The CLI is the unchanged session CLI, with its five positional arguments first, but invoked through this new script. The session output basename must contain `diagnostic` and must be new. A separate sibling `<output>-diagnostic-host/` records the extension's exact source snapshot/hash, unchanged base source8 hashes, pexpect version/base-expect source, forwarded argv, tail termination/elapsed time and explicit exclusion. It does not pre-create the actual session output or alter the wrapper's lock-before-mkdir rule. Metadata is valid JSON with a real trailing newline. No new guest/runtime option is introduced, and there is no automatic launch or retry here.

Ten host tests use fake low-level expect/session behavior only. They verify the exact20-second parameter, single-window budget, tail retention, exact failure-match identity restoration, normal PASS/no-trigger behavior, EOF/TIMEOUT/read errors, cancellation, JSON round-trip and delegation/restoration. A test through the **unchanged real guest guard/run function** proves the extra fake call trace is retained while status remains FAIL and the original forced-close path still executes. These are software checks, not target evidence.

The original failure remains incomplete and excluded. This wrapper adds observation time after detection; it does not identify the callee, explain EPC0, establish a leak from page-fault counts or repair an instruction/data fault. Any captured diagnostic must retain its extra-source identity and be reviewed separately from frozen cohort results.
