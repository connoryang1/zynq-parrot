This reviews changing only the inference of shallow prefetch fill banks, not retained payload storage. The current source has four slots on both I and D, while the r4 DCP maps each side's eight64-bit beat banks to eight RAMB36 tiles. Distributed inference is a smaller cycle-behavior change than delayed pending capture, but no measured LUT cost or freed-tile result exists for this proposal.

I uses `prefetch_els_p(4)` at `bp_unicore_lite.sv:451`. D uses `dcache_prefetch_els_p` at587: the actual `prefetch16k_cfg` inherits `prefetch_cfg` (`cosim/black-parrot-example/v/bp_common_pkg.sv:164–171`), whose override at118 sets four. The generic default of two and separate five/ten-slot configurations do not describe this endpoint. Each `bp_uce.sv:964–974` bank is64bits×4slots; all eight output registers are read in parallel every enabled clock. The explicit `ram_style="block"` is the resource choice. The existing r4 hierarchy reports eight BRAM tiles per UCE and identifies the bank RAM instances, so there are sixteen *existing mapped sites to target*, not a proof that a changed attribute removes all sixteen. Raw stored-bit counts do not establish implementation area.

The current HDL on a clock edge performs optional `mem[response_slot] <= response_data` and unconditional `install_word <= mem[install_slot]` under the same `prefetch_full_line_p` enable. Nonblocking assignment semantics make a same-address collision return the old word to the output register, with the new word visible to a read on the next edge. There is no RAM reset or added serialization. A selective distributed candidate must preserve that data-output register, its enable and this old-data rule. Merely registering the read address and exposing asynchronous RAM data is different: a write can change the apparent current-cycle result after the edge, and address/data activity can escape between edges. Do not add a collision-don't-care directive or change read/write order to force inference.

Local installed **vendor primary sources** support the distinction, so no web lookup was needed. Vivado2024.2 `data/ip/xpm/xpm_memory/hdl/xpm_memory.sv:620–626` rejects non-read-first modes for distributed single/true-dual-port RAM, and757 likewise requires read-first on the simple-dual-port read side. Its synchronous read template retains the output register. `data/verilog/src/unisims/RAM32M.v:129–152` models rising-edge writes with100ps deferred memory updates and asynchronous read outputs; its timing section includes write-address/data setup/hold checks and notifiers. Thus a correctly timed same-clock output FF can retain the old value before the RAM changes. These model sources do **not** prove which primitive Vivado will choose for this HDL or guarantee a collision result after an address-registration rewrite. They also do not authorize independent read/write clocks or ignoring physical hold timing. Production clocks/enables must remain unchanged, including the D-side phase.

Same-slot read/write collision is a real case worth preserving even if downstream control usually waits: the final reply word and continuous install-slot read can coincide. Newly complete slots enter the installer through drain/tag-scan states, so an old read at that edge normally refreshes before publication; do not use that latency to waive cycle equivalence. A retired slot can later be reused, install-slot selection changes, cancelled responses still drain, and read outputs continue updating without writes. None of these should gain new write-through, hold, reset, extra latency or ready gating. Backend-owned insertion still receives a stable complete line under its existing ownership/cancellation rules.

The smallest useful future gate has two layers, **neither run here**. First infer the original and attribute-only bank groups in fresh isolated Vivado2024.2 jobs with exact four-slot/64-bit/eight-bank ports and all ports variable. Bind the source extraction/attribute-only diff, actual command, tool version and generated netlists. Require actual distributed RAM primitives and zero RAMB primitives in the candidate bank hierarchy; compare adjusted LUT sites split logic/memory, FFs, muxes, BRAM and timing against the original. Do not accept a macro/attribute echo as inference proof. A larger-slot fallback may remain block RAM, but should be a separate constant-bound inference case rather than quietly changing all configurations.

Second cycle-miter the **actual two inferred netlists** with vendor primitives and explicit initialized-word validity, not merely two identical behavioral arrays whose attributes a simulator ignores. Seed all slots with distinct nonzero data and compare all512 registered output bits after clock-to-output settling on every defined read. Exercise no-write reads, same/different-slot writes, each bank, consecutive beats without bubbles, moving/held install slot, final-complete/next-slot turnover, cancellation/retirement and reuse. Output-register hold/enable and old-data collision behavior must match on the same edge, not one cycle later; both arrays are intentionally unreset and uninitialized words must not create false proof. Retain actual mapped primitive identities so a passing miter cannot compare two still-BRAM implementations. Then use the existing real UCE/backend gate to confirm complete payload, owned-publish backpressure/clear/disable and no changed architectural handshakes. This is narrower than a new whole-core run; full integration remains a later admission decision.

Compared with the completed-capture snapshot proposal, this attribute-only candidate introduces no new completed address, due-valid, kill tracking, idle term or advisory latency. It is therefore the smaller causality experiment **if inference and read-first equivalence hold**. Its resource direction is different: r4 is already LUT-overfull and BRAM-full, so trading shallow BRAM for LUTRAM can worsen LUT pressure even while opening payload/metadata BRAM space. “Modest LUT cost,” sixteen freed tiles, successful fit and extra retained capacity all require measured mapped/whole-top results. Delayed pending capture instead targets a logic cone but has unmeasured savings and new scheduling hazards. Keep the changes separate when judging either result.
