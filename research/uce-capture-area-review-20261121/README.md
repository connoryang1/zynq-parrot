This reviews one small UCE logic-area candidate after the r4 whole-FPGA fit failure. It binds the existing synthesized DCP hierarchy reports and immutable SP source, and proposes a correctness boundary before implementation. No RTL, model, synthesis, physical-board or application run was changed or started for this review.

The DCP is `3514bf6fd563fae17e6b8c4829810b7d60b706b85c79995f05a501361e247663`; the query reports Vivado2024.2, xc7z020clg400-1 and design state **Synthesized**. Its flat report uses57,373/53,200 LUT sites:53,776 logic plus3,597 memory, and140/140 BRAM tiles. Focused D UCE uses2,460 LUT sites (2,222 logic/238 memory), I UCE2,703 (2,515/188); each uses eight BRAM tiles. Retained storage is3,756 logic LUT sites and41 BRAM. These are actual synthesis reports, not a routed timing result. The UCE totals are not removable-overhead estimates and a candidate cannot be assumed to close the4,173-site excess.

The source is immutable BPd766d42cdf04ee43ca1e915fb9da06f5cc117dde. In `bp_me/src/v/cce/bp_uce.sv:890–950`, only an accepted ordinary cached full-line load refill updates `retained_capture_data_r`; its actual physical fill index selects the64-bit destination in a512-bit line. A complete full-beat mask, final accepted beat and demand-capture/cancel/clear/matching-mutation guards allow publication to the optional pending line. On that same edge both capture and pending registers receive `retained_capture_next_data`. Thus pending's input includes a per-word current-response bypass from `fsm_rev_data_li`, selected by physical fill index; a plain registered copy would be missing the final word. Capture and pending are both real512-bit staging registers, separate from the retained1280-line payload.

**Bounded candidate:** retain both line registers and all ordinary geometry/transport. On the accepted full-mask final beat, capture the final word and independent completed-line address/valid metadata. On the following edge, copy the now-complete registered capture line to pending. Per-word capture enables should remain explicit/recognizable so the capture register can update one word without a wide feedback mux. This removes the *need* for the final-word bypass at the pending input, not the need for capture itself, and adds no retained-payload BRAM. It adds one cycle to advisory availability and can alter demand-versus-prefetch insertion order. It is not cycle-equivalent replay scheduling and old performance data cannot describe the new path. Actual LUT reduction depends on Vivado sharing/CE mapping and must be measured; no numerical saving is established.

The minimum invariant is: every newly valid pending line equals all eight accepted words of one completed physical refill, with that refill's immutable full physical address; no cleared, disabled, aborted, partially received or matching-mutated generation becomes insertable. The extra stage must not feed backpressure into ordinary request/reverse/cache SRAM handshakes or alter critical/last/done, dirty-victim writeback, uncached or store/LR/AMO paths. Accepted backend lookup/insert ownership still drains normally.

Specific hazards constrain the implementation:

- A next ordinary request may replace `cache_req_r` before the delayed copy. Latch the completed physical line address separately; do not early-overwrite an older valid pending address or compare a kill against the next request's address.
- The copy reads pre-edge capture data, so a next refill's first word can update capture on that same edge without contaminating the completed snapshot. Preserve this nonblocking-assignment boundary, and preserve the completed-mask provenance. A generic single-beat full-line configuration also needs ordered old-due copy/new-due creation when consecutive lines complete.
- Clear/accepted maintenance, demand-capture disable, I abort and matching D mutation must kill the completed-but-not-yet-pending generation. Same-edge kill wins copying/publication, and re-enabling cannot resurrect it. Compare the completed address, including high physical bits; the existing pending/request comparisons alone do not cover the new stage.
- If an old pending line is accepted while the delayed snapshot becomes pending, the backend must receive the old address/payload and the new pending must survive for later insertion. A held backend/old insert may cause optional pending replacement as before, but never mixed metadata/data. Existing owned-insert source/address/cancel bookkeeping stays unchanged.
- `retained_idle_o` must explicitly include absence of the new completed-copy stage. Otherwise a gap after architectural completion can falsely advertise UCE/client/backend idle before queued copying is resolved. This remains a mechanism boundary, not global L2/AXI quiescence.

Other selectors are real but are not better justified first edits here. UCE `retained_insert_data_o` selects a complete demand-pending versus prefetch-install line at876; `retained_hit_data_r` selects one of eight64-bit words at1305. Full-prefetch SRAM outputs feed `prefetch_install_line_r` at964–972; the reports identify eight RAMB36 bank instances in each UCE. Removing those buffers or serializing their shared interfaces would change ownership/overlap and is broader than the pending-copy change. Backend `insert_data_r[word*64+:64]` is another eight-to-one write-word selector (`bp_retained_line_store.sv:170`), while the metadata/RR/epoch mux work is separately underway. Register counts alone cannot decide that a shift/rotation rewrite saves LUTs; it may replace one read mux with a wider load/shift mux.

The current DCP query groups all UCE primitives together and retains only four name samples per primitive/reference group (`query.tcl:58`). It does not enumerate capture/pending D cones, so the aggregate LUT3/LUT6 or FF counts cannot attribute a measured saving to this bypass. The cheapest additional *read-only* attribution, if desired by root, is the union of combinational fan-in to actual pending-register D pins, separated from capture-register D/CE and the insertion-output source mux, with shared cells deduplicated. Do not sum raw LUT primitive counts as if they were adjusted LUT-site utilization or claim that every cone cell disappears after rewriting.

The reusable existing harness is `testing/rtl/run_uce_retained.py` with `uce_retained_tb.sv` and `uce_retained_driver.cpp`. Its unexecuted proposed entry points are `python3 testing/rtl/run_uce_retained.py --out NEW_D_DIRECTORY --lines 64` and the same command with `--icache --out NEW_I_DIRECTORY`. The runner records actual commands/source hashes, uses `--assert --trace-fst --cc --exe --build -j2`, enforces240s build/60s run bounds and runs the specific short-response assertion/drain negatives. It supplies four-set/eight-way L1 endpoints and a64-set backend on one local clock, not the full FPGA's256 retained sets/core topology. `step()` samples handshakes before each rising edge. `request()` adds metadata cycles; `response()` sends aligned logical words0..7 and inserts a low-valid `step()` after **every** accepted beat. Therefore it does not establish continuous reverse traffic, every legal critical-first physical-index ordering, earliest next-request turnover or a simultaneous old-pending handoff/new-snapshot copy. Existing I-abort-normal and queued-final tests (164–171) cover cancellation around returned traffic but not the proposed new stage's exact edge; owned-prefetch clear/disable tests (132–142) must remain unchanged.

Before any implementation is accepted, the smallest useful functional gate is the existing real UCE/backend64-bit I/D gate plus a precise zero-gap extension: finish lineA at every critical-first offset, accept the first word ofB on A's delayed-copy edge, and check all512 bits plus PA at insertion. Exercise backend backpressure and old-pending accept/new-copy turnover; inject clear/disable/I-abort/matching-store on last, copy and accepted-insert edges; confirm no publication or false idle, and verify ordinary critical/last/all-eight L1 writes and dirty writeback remain unchanged. Keep the existing partial/wrong-size assertion-disabled drain and owned-prefetch cancel cases. The present driver calls `step()` after each response beat and `idle()` after each demand (`uce_retained_driver.cpp:91–99`), so its existing capacity sweep does not establish that zero-gap boundary. No new test was written or run here. If authorized later and the focused gate passes, compare exact whole-top synthesized LUT-site/BRAM/timing results on the same source/config, then retain strict whole-core payload/retirement proof before interpreting fit or application effects.
