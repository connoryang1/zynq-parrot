The default libcma allocator returns NULL on a failed allocation ioctl, nonpositive returned ID, or MAP_FAILED from mmap. The header's “-1 on failure” comment does not describe this path; no NULL-versus-MAP_FAILED bug is established here. The default path uses ioctl 0xc0045802, the requested mapping length, raw flags 0x2001 and a returned-ID-derived offset. It records the returned physical address and ID, but stores the requested length. That table is not an independent returned-extent witness. An optional allocator callback can bypass this default path, so active NULL hooks or the exact callback semantics must also be bound.

Default free clears the matching userspace table entry, unmaps its stored length and issues ioctl 0xc0045803; it does not check munmap or ioctl results. Reset issues ioctl 0xc0045865, prints negative errors and returns void. Kernel allocation, mapping, ownership, reset and release semantics still require matched driver evidence. Neither the free print nor normal application return proves successful release or safe hardware quiescence. No driver defect or actual use-after-free is claimed.
