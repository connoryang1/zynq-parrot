This directory records narrowly scoped maintenance after the Linux session16 staging upload exhausted board storage. It removes only three complete files created by this task whose bytes match retained host copies. It does not reclaim other agents' files or diagnose application failures.

The executable `cleanup_own_staged.py` acquires the shared immutable session flock before any board inspection or modification. It also uses the repository runner's board-side mkdir/owner-PID lock protocol, checks for an active control-program process, inventories the fixed whitelist and verifies each full hash against a durable host copy. It rechecks identity and content before unlinking. It neither resets nor reprograms the board.

The first attempt stopped before inventory or deletion because it incorrectly assumed that the board program lock was a regular flock file. The actual runner uses a directory. That failed manifest is preserved at `/home/coyang/fpga-artifacts/context-resume/natural-demand-20261120/maintenance-own-staged-cleanup/maintenance.json`; the corrected attempt's manifest is in the adjacent `maintenance-own-staged-cleanup-v2/` directory.

The corrected attempt removed only this task's superseded c7, d14 and uncapped embedded-baseline NBF copies, all with exact matching retained host hashes. Free space increased from 4,657,152 to 216,330,240 bytes. A partial incoming upload did not match the expected local prefix and was skipped. The global lock inode, accepted images, bounded images and other task artifacts were preserved. Session17 subsequently completed both workloads after fresh recovery, although its legacy unscoped WHOLE measurements remain diagnostic only.
