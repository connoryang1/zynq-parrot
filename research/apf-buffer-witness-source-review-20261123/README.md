This source-only review identifies what can and cannot witness a live old2dd CMA buffer. The pinned APF source has no public per-buffer query ABI, so the proposed first probe gathers metadata only and deliberately cannot certify an allocation extent or uninterrupted lifetime. No board, SSH, process-memory, physical-memory, MMIO, ioctl, CMA library call or controller action was executed here.

Source contract and limits:

- xlnk.c:81–89 stores4096 private entries: allocation pointer, DMA anchor, requested buflen, cacheable, user VA and process PID. Allocation349–379 fills pointer/len/DMA under a spinlock. Ioctl693–718 returns allocation ID/DMA address. All ioctls1456–1505 are operational; none enumerates/queries existing buffer state. read/write470–507 address only the unrelated8192-byte dev buffer, not these arrays. Do not open/read the device as if it exposed stats.
- mmap1514–1554 derives kernel slot from VMA offset>>(16−PAGE_SHIFT), maps using the DMA anchor, and records user VA/current PID. It DOES NOT check the requested VMA length against buflen. Thus a /dev/xlnk VMA maps to a candidate slot via byteoffset>>16, and its length is a mapping length, not authoritative allocated length. remap/PFN ownership, requested length and physical contiguous extent must not be conflated.
- free724–755 clears pointer/DMA/len before dma_free; process/userVA fields are not cleared there. release514–517 does nothing; VMAclose1562–1565 only decrements a counter. recover_resource1570+ frees all buffers, without owner filtering. A live PID, FD or VMA does not alone prove that its allocation remains live. Duplicate/remapped VMAs can overwrite the one process/userVA tuple, so that tuple is not exclusive ownership either.
- ARM32 userspace typedefs in xlnk-sysdef.h give32-bit pointer/int fields, but kernel dma_addr_t width must be established independently from actual config/ELF/type evidence. Never assume every kernel array element is32bits from the userspace ELF class. Private symbols may be absent when KALLSYMS_ALL=off; a missing or redacted address is not proof a record does not exist.

The source-derived ELF-virtual table candidates are recorded in evidence.json, not runtime addresses: actual ELF PT_LOAD/bss extents, process load bias and runtime allocator-branch ownership remain unproved. No table address/entry is read by this first probe, and no libcma/pynq import or getter is called in another process.
