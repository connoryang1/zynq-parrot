This audit derives the accepted f091 package's cache geometry from its exact recorded source revisions and static configuration. It compares that inference with actual FFC trace parameters and the separate RL106 L2 control. No build, elaboration, target execution, or board I/O was performed.

The accepted named CFG inherits both 32 KiB L1 geometries from the BP schema. Its base sets one L2 slice and one bank; the named prefetch override selects two banks and divides the base's 32 sets between them. The separate named 16 KiB endpoint is not the configuration recorded for f091. The recorded default thread/context flags resolve to two resident slots and four logical contexts, with one cache instance per core shared by them. No routed VDS/DCP was recovered, so these accepted-package values remain source inference, not independently verified route elaboration.

The I advisory store holds 32 complete 64 B lines, **2 KiB total**, with four hashed tag banks of eight ways. Its four UCE transaction slots and its 256-entry address controller do not increase that retained payload capacity.

The D store is global to the cache instance: its arrays contain four physical-address tags, two word-valid bits per tag, and eight 64-bit data words. There is no thread/context dimension or context tag. Words are consumed individually; matching stores or ordinary L1 hits invalidate the corresponding segment. Four UCE request slots, a four-address preview queue, a two-command replay queue, and four software footprint slots of 32 addresses are separate metadata/control structures.

`prefetch_full_line=0` selects a **16 B logical BedRock read**. With the selected 64-bit fill path, its logical response is two 8 B words; it does not forward a 64 B UCE line and retain only 16 B. Direct physical-preview CSR`0x9c0` discards replies. Tagged physical replay, configured through`0x9c1/0x9c2` and triggered by`0x9c3`, instead injects`e_dcache_op_prefetch` into the cache-request path; its UCE allocation sets`prefetch_preview_r=0`, so narrow replies can populate the D advisory segments. The explicit Linux data-replay prctl uses this tagged path. Physical-address input does not imply reply discard. Under the recorded static/default path, D requests traverse L2. A lower-level miss can require a 64 B block fill, but source alone establishes no physical AXI byte count, bandwidth cost, interference, or performance effect.

Equal total L2 bytes do not make the FFC and accepted configurations interchangeable: their bank mapping/concurrency and D advisory capacity differ. The existing full-access FFC audit rejects accepted prefetch requests or consumed side hits; it validates the normal-cache baseline only. RL106 changes L2 sets, not L1D or advisory-store capacity, and supplies no general application speedup claim.

The retained Linux [configuration handler](../retention-kernel-20261120/accepted-rootfs/accepted-kernel_sys.c#L2905), `PR_BP_PREVIEW_REPLAY_CONFIG=0x4250505c`, writes footprint entries through CSR `0x9c1` and configuration through `0x9c2`. The [explicit trigger handler](../retention-kernel-20261120/accepted-rootfs/accepted-kernel_sys.c#L3020), `PR_BP_PREVIEW_REPLAY_TRIGGER=0x42505060`, writes the configured slot to `0x9c3` when enabled. The [retained UAPI constants](../retention-kernel-20261120/input-include_uapi_linux_prctl.h#L320) name these commands. The CSR write passes through the retired-thread mux, replay controller and PMA guard; `pipe_mem` supplies a physical ptag and injects `e_dcache_op_prefetch`. Dcache then emits `e_cache_prefetch`, whose UCE allocation sets `prefetch_preview_r=0`. CSR `0x9c3` bit2 selects instruction follow behavior; it does not select the direct-preview discard path. Only CSR `0x9c0` drives the separate UCE `preview_v` ingress and sets `prefetch_preview_r=1`.

[replay-path-source-proof.json](replay-path-source-proof.json) freezes exact accepted git blobs, SHA-256 hashes and numbered excerpts for these routes, bridge modules, Dcache/UCE decisions, the default bypass setting, the allocating normal L2 load/fill path, and the retained kernel handlers/UAPI. These sources establish that tagged replay **can** populate the global 64 B D advisory store and prime L2. They do not establish occupancy at first use, actual side hits, measured physical traffic, or performance attribution. UCE drained status does not report advisory-word occupancy.
