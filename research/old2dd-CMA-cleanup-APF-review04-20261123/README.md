The new 04 machine code closes the missing-main gap. Exact 2dd requests 48,234,496 bytes with cacheable=0 at 0x3426–0x3454. Its cleanup calls cma_free at 0x3d04 before writing DRAM_INITED=0 at 0x3d1e. The preceding path exits the host-finished/runtime-limit loop, emits the watchdog tag sequence and 50 idle writes, then prints/stores diagnostics. There is no explicit core-freeze command or HP0 outstanding-transaction completion acknowledgment in that host cleanup path. Stop/done remain print-only. This is a concrete hardware-quiescence qualification gap, not proof that DMA actually occurs after free; a terminal guest/firmware guarantee could still establish safety.

Pinned a44 top_zynq source declares and assigns dram_init_li, but does not use it to gate HP0 traffic. Therefore merely moving the DRAM_INITED clear before free would not establish safe release. Actual physical source and terminal semantics must be bound. The new SDS trampoline slice completes the default libcma routing: noncacheable passes flag0 to xlnkAllocBufInternal, and sds_free calls xlnkFreeBuf.

The public Xilinx 2020.1 APF source explains the observed ABI. Allocation calls dma_alloc_attrs(requested length), records the resulting allocation pointer, DMA address, length and cache attribute, then returns an ID and address. mmap derives that ID from the offset, makes cacheable0 mappings noncached, remaps the address and records PID/user address. A successful, deployment-matched allocation chain can be meaningful extent evidence. A VMA length alone cannot: this mmap function has no explicit requested-VMA-length versus recorded-buffer-length check. Actual ARM DMA backend/address semantics and deployed implementation identity remain necessary.

Free uses the recorded kernel allocation/length/address with dma_free_attrs. Driver close is a no-op; VMA close only decrements a count. Reset ioctl101 frees all buffers and releases APF DMA channels, without a BlackParrot-specific HP0 drain guarantee. Its global handle tables are not protected by per-process ownership in the free ioctl. The common reservation and independently verified absence of foreign users/resets therefore matter. The driver exposes static allocation tables but no per-buffer read-only proc/sysfs/query-ioctl interface; read(/dev/xlnk) reads a generic device buffer. Privileged table inspection would need exact deployed symbol/layout identity and coherent repeated reads. No such access or observer ran here; FTRACE and CMA_DEBUGFS are disabled.
