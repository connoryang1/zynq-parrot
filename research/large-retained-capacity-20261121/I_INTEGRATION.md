This note records the opt-in I-cache integration with the shared full-line BRAM backend. Its directed simulations establish payload and cancellation behavior; they provide no FPGA fit, timing, Linux stability, or application performance result.

The owned RTL is `bp_fe_icache.sv` and the new `bp_fe_icache_retained_bram.sv` adapter in `import/black-parrot/bp_fe/src/v`. Root owns the common configuration, CSR and top-level wiring; `bp_retained_line_store.sv` is the generic backend owner's implementation. `replay_buffer_bram_p=0` keeps the historical asynchronous retained store as the default. Large mode constant-prunes that store to a disabled dummy entry and exposes one scalar lane to the shared backend, rather than instantiating another private payload array.

Normal L1 hits issue no side lookup. A translated, nonspeculative, cacheable physical L1 miss waits for synchronous tag/payload lookup; a miss then follows the original UCE path. A canceled accepted lookup keeps its ownership until its exactly-one backend response arrives, preventing an old reply from becoming a new fetch. Only live response handshakes can produce a consumed side hit. All normal permission, uncached, abort and fence paths remain upstream of this lookup.

Accepted ordinary refill beats and detached advisory beats have separate source/generation state. Four 128-bit beats produce an atomic 512-bit insertion only when the complete beat mask is present. Critical-first demand order can start at any beat; beat zero in the middle does not reset it. A registered capture stage, one complete-line pending slot and one backend insertion in flight never backpressure required SRAM writes; a full queue drops the entire new optional line and pulses `retained_drop_o`. This finite capture throughput and its drops must be charged in later workload evidence.

`retention_lookup_enable_i=0` bypasses lookup latency and suppresses all new large-path admission, including late advisory packets. It kills partial/pending captures and cancels accepted insertion, while retaining accepted lookup/insert ownership until response/done. Mode zero with lookup enabled permits advisory-only capture; nonzero existing modes admit ordinary demand. Mode two uses the backend's no-replace physical-set policy, which differs from the old four hashed banks. Large mode conservatively reports the old combinational replay-resident query absent: replay refreshes are unsuppressed and their real costs must be measured. No claim of identical policy placement or refresh suppression is made.

`retained_idle_o` covers the adapter's pending/accepted query and insert, partial assembly, registered capture and ordinary demand token. It excludes the backend's separate busy/sweep state and excludes outstanding UCE traffic. It must never be described as draining the whole memory system.

Reproducible focused commands (fresh `--out` and `--evidence` directories required):

```sh
python3 testing/rtl/run_icache_retained_bram_adapter.py --sanitize \
  --out /dev/shm/i-adapter --evidence research/large-retained-capacity-20261121/i-adapter
python3 testing/rtl/run_icache_retained_large.py --lines 64 65 128 256 512 1024 \
  --out /dev/shm/i-large --evidence research/large-retained-capacity-20261121/i-large
```

The adapter's final `adapter-09` gate passes with host AddressSanitizer and leak detection explicitly disabled because LSan cannot inspect threads under this managed ptrace sandbox. It checks cancellation ownership, response stalls, hit/miss release, full payload assembly, critical-first wrap, source isolation, bounded staging drops, clear, disabled late capture and insert cancellation/publication. This is not leak-freedom evidence. The real-I-cache gate fills the configured count of distinct physical lines through ordinary demand, clears only ordinary L1 tags, and checks every one of the eight retained words per line. It separately checks unchanged L1-hit behavior, advisory-only admission, runtime bypass, MMU/uncached guards, pending redirects, partial abort and fence invalidation. These paced fills establish actual stored payload capacity, not sustainable admission throughput or useful capacity for arbitrary conflict patterns.

The clean, source-stable `i-capacity-final-01` matrix passes at 64, 65, 128, 256, 512 and 1,024 complete lines (4,096 through 65,536 payload bytes, including the 65-line partial final way). The largest test checks all 8,192 retained 64-bit words after ordinary tag removal. Each capacity retains its build command/log, closed FST, run log, model hash and source/dependency hashes. `i-legacy-final` independently passes the historical 32-entry runtime-mode, pin/RR, critical-first, abort/fence and saturated-statistic regression with the opt-in parameter left zero. Full-core translated/context-switch validation and routed FPGA fit/timing remain root-owned pending gates.

After the generic owner's zero-capacity elaboration fix, `i64-zero-fix` repeats the clean real-I-cache gate and passes with that exact updated backend. The six-capacity matrix remains bound to its original backend snapshot; both backend versions and the exact compiled test inputs are retained as gzip source snapshots. Removing one extra EOF blank line from the maintained wrapper after the matrix changed no stimulus logic and is disclosed in `i-verification.json`.

Preflight failures are retained, not counted as acceptance. `adapter-03` exposed a procedural output declared wire and was corrected to logic. `adapter-04/05` failed in test teardown; `adapter-06` AddressSanitizer localized the use-after-free to global FST teardown after Verilator's static callback registry, corrected by giving the trace a local lifetime. `adapter-07` caught a test macro/method name collision, corrected to an explicit pointer. `adapter-08` completed all functional checks but LSan could not run under ptrace. `integrated-01` checked all 64 payloads then timed out because the synthetic engine did not send the terminal discarded beat of an accepted aborted UCE request; the wrapper driver now models that required drain. The initial `i-baseline` build overlapped source edits and is preflight only, irrespective of its printed PASS or post-run source hashes. A separate clean, fixed-source legacy regression replaces it.
