The one new candidate is **lossless encoding of the inactive CSR snapshot payload using its existing architectural compressed types**. Keep the two resident CSR banks, independent IRQ/debug/counter evolution, every read/save/restore owner and all concurrent operations. Change only the representation inside the four-context inactive store, with combinational encode/decode at that boundary; no new arbitration, state-sharing between contexts, latency or policy.

There is an actual source-and-inference reason to inspect this boundary. Frozen `bp_be_top.sv:363–386` has one accepted save/seed write, one address and the common `csr_context_save_data_lo`; the inactive store is not an external arbitrary-data producer. `bp_be_calculator/bp_be_csr.sv:280–308` constructs that bus from26 **expanded64-bit** CSR values plus2 privilege bits. Each CSR is already held internally as its smaller `bp_*_s` type through `bp_common_rv64_csr_defines.svh:1060–1069` and the corresponding existing compress/decompress macros. The complete1280 SYN `.../black_parrot_bd_proj.runs/synth_1/runme.log:2213,2426` nevertheless lists `csr_snapshot_store | mem_reg | User Attribute | 4 x 1666 | RAM32M x278`. This is an inference/mapping-table attribution, not proof that278 macros or1112 LUT sites are all removable after downstream optimization.

Examples of source-encoded information duplication are concrete: `bp_mstatus_s` has15 state bits expanded to64 (defs325–374); `bp_mcause_s`/`bp_scause_s` have interrupt+4-bit code expanded to64; `bp_fcsr_s` has8 bits expanded to64; physical counters have48 bits expanded to64 (defs981–991). This subset alone contains255 expanded bits per saved image derivable from those fields. Address sign extensions, fixed bits and other masks require the exact parameterized macro semantics, not a hand-written assumption that reserved bits are always zero. Full64-bit scratch registers and distinct privilege/debug/counter state must remain independent. No physical LUT/slice saving is claimed from bit arithmetic.

The proposed codec uses the exact existing `compress_*`/`decompress_*` pairs with the same vaddr/paddr/extension parameters; it does not redefine WARL behavior. Every accepted snapshot write already equals the current resident save expansion E(q). Required proof is `E(C(E(q))) == E(q)` for every reachable resident image q, including debug/trap/counter/ASID states, not merely for Linux-observed values. The root-level write qualification, save/seed address priority, reset-valid behavior and asynchronous read cycle stay unchanged. The unpacked valid1666-bit read image must equal the old saved image before any consumer uses it. The restore path at CSR864–928 already recompresses fields; resident initialization bypass at top423–426 must remain outside or exactly traverse the same identity-preserving codec.

This is **not** a generic1666-bit RAM replacement: arbitrary noncanonical1666-bit writes cannot be represented losslessly by the smaller type. The existing generic store and its all-bit arbitrary-input tests cannot silently be weakened or relabeled. A production adapter needs an assertion that every accepted input is canonical, while retaining the old out-of-range zero/valid interface and existing qualified-invalid-read contract. Do not add invalid zero masking—the previous measured mask cost is a warning. No CSR semantics may be discarded because software does not use them. If the real save bus has any independent bits not covered by the codec, keep them explicitly; inability to prove reconstruction blocks this candidate.

The smallest useful first gate, only after ROOT selection, is a real two-bank CSR producer/consumer plus four-context snapshot store/controller-cut comparison using the same actual CFG and exposed ports as the accepted primary CSR gate. A bare narrow-memory or all-variable raw1666 wrapper cannot establish this candidate. Compare all outputs, every valid decoded snapshot and independent bank state under arbitrary CSR writes/RMW resolution, simultaneous other-bank restore/APC/IRQ, save versus seed/rebind, traps/debug, counter carry/inhibit, extension flags, reset/invalid/out-of-range accesses and original ownership priorities. A mutation dropping a live cause/counter/address bit must fail. The canonicality/reconstruction assertions are required on every accepted write/read. Pure combinational encode/decode adds no cycles or port serialization.

Then one matched component mapping would compare **unchanged unmasked RAM representation** versus encoded RAM with identical real CSR banks/consumers, production synth settings/clock/options, all outputs live and zero blackboxes. Record actual width/primitives, LUT logic/LUTRAM, FF, control sets, physical packing and timing. This measures net decode/encode versus storage cost and permits a neutral/adverse result; no whole-device saving follows automatically. Only if that evidence justifies it would clean fullcore/architectural/context and separately admitted full-fit gates be appropriate. No such component or new whole-device run is requested or funded here.

No second high-value candidate is justified in this bounded review. Resident/virtual NPC and dirty metadata have separate update/launch/reseed lifetimes; two mirrored operand RFs provide real parallel reads; RPC argument shadows and pending-call payloads must survive different write/speculation windows. Per-bank cycle counters can evolve concurrently, so one selected retirement adder cannot replace their independent increments. Duplicate-looking names and state widths are not a proof of safe deletion. The active capacity bisection continues without any source or policy change.
