This source-only review tests whether sharing the core-global custom-CSR command decoder is a credible response to R9's166-slice placement deficit. It finds a behavior-preserving sharing boundary, but no defensible hundred-LUT saving: wide payload outputs are aliases of one bus, and the ordinary per-bank CSR updates still need the existing bank gates. No RTL, probe, test, compiler, model, vendor, launcher or board operation was run; no storage04 work is repeated.

Recommendation: do not prioritize or build this command-only candidate on current evidence. A zero/few-tens incremental LUT result is plausible; there is no measured saving and no credible source argument that it addresses166 slices. This is an explicit negative prioritization finding, not rejection of all future CSR optimization.

The reviewed source is BPbb575a764c200f07c6f3259a179bdc861dd7593f (BE files identical to8df). The prior audit's candidate2 covered shared global read/status and command decode. Exact sharing boundary

- bp_be_csr_wrapper_mt.sv:221–228 gates the complete retirement packet and context-switch bit by retire_thread_id_i. Lines231–329 instantiate one complete CSR engine per resident bank. Lines362–386 then select all ten global command families and their payload fields using THAT SAME retirement owner. Read-owner/current-owner/save-owner muxes at332–355,387 are different and must stay different.
- bp_be_csr.sv:394–396 defines W = retired.special.csrw & ~retire_ctxtsw, data = retired.data, address = retired.instr.imm12. The command equations at1087–1154 use only these values, bank-local current privilege/debug-as-M, uniform retained_buffer_p and payload slices. Their local command outputs do not feed back into architectural CSR storage. A wrapper-only implementation could open these unused per-bank command output ports and compute the same expressions once, choosing m_mode/s_mode from decode_info_co[retire_thread_id_i]. No bank-state interface or new global state is needed; keep standalone bp_be_csr unchanged. This remains a proposal, not implemented RTL.
- For legal owner r, retire_pkt_gated[r]=raw retire_pkt, retire_ctxtsw_gated[r]=raw context-switch, and decode_info_co[r].m_mode/s_mode equal the original bank's is_m_mode/is_s_mode (CSR lines211–215,1019–1022). Therefore old selected command output = F(raw packet,raw ctxtsw,selected bank CURRENT registered privilege). Same-edge restore/debug/IRQ must retain old-state combinational semantics, never use priv_mode_n. No current_physical_thread_id or reservation owner substitution is valid.
- RMW is already computed ONCE upstream, bp_be_pipe_sys.sv:323–355: CSRRS/CSRRC/immediate transforms feed retire_pkt.data. The proposal must consume this resolved value. It must not recompute operands from reservation data or move RMW between pipeline stages.

Why the apparent wide duplication is not hundreds of independent mux bits

Each per-bank command payload is csr_data_li or a slice: full64b dcache_replay_payload; low physical-address slices for replay/entry/preview; indices/counts/range/mode bits from the SAME data bus (CSR1096,1108–1114,1120–1129,1138,1154). The wrapper selects each family by the same retire ID. For any bit d and one-bit owner r, selecting gated data is r?(r?d:0):(!r?d:0)=d. A SINGLE shared64b selected bus can serve every alias, so multiplying64b by the number of output names is incorrect.

Even a naive128 single-bit input-gate +64 single-bit output-mux description is NOT a removable-cost bound. The ordinary per-bank CSR updates still require bank-isolation semantics (CSR668–708 and retirement gating); hoisting cannot claim the128 input-gate bits as savings. Synthesis may already absorb that gating into enables, so there need not even be128 physical AND gates. Only the global-output selection cone is a candidate. At most one64b selection bus plus address/control gates is independently implicated before synthesis sharing, not one wide mux per output. A LUT can absorb multiple Boolean operations, the selector/gates can collapse algebraically, and existing synthesis already merges some cross-bank structure. Consequently source gate counts cannot establish a positive LUT delta, let alone hundreds. No payload FF is removed. Wider global-read refactoring is a separate unreviewed change and is not silently added to rescue this candidate.

Smallest realistic measurement envelope, ONLY if later justified/selected

A bare comparator or isolated mux probe is inadequate because it removes the standard-update consumers that keep bank data gates live. The smallest meaningful area comparison is a paired EXACT two-bank CSR wrapper, same production cfg/paddr34/retained_buffer1/50ns clock, same live IRQ/restore/cfg/retirement/read and every visible output, all bank states independent. Candidate changes only global command output selection. Preserve live ordinary update consumers and all context-image outputs so the intended cones cannot be pruned away.
