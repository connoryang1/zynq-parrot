# Private POSIX log-filter workload preparation

This prepares a real libc regex workload for a later retained-cache experiment without changing the frozen plain benchmark. It validates functional results and the accepted Linux runtime ABI; it is not RV64 execution or a performance result. The prior regex preparation supplies the reviewed schema and accepted-runtime proof helpers, while this module adds the requested fixed 64-query transaction API.

`linux-tests/retained29_regex_workload.h` exposes `retained29_regex_init(w, kib, seed)`, `retained29_regex_run(w)`, `retained29_regex_check_total(w, sum)` and `retained29_regex_free(w)`. Initialize fresh or freed storage; initialization returns 0 or -1. Run returns a transaction checksum; callers sum it modulo 2^64 and require the final boolean check, which also rejects sticky errors. A checksum equal to `UINT64_MAX` alone is not an error discriminator. Free is safe after initialization failure and is repeatable. The process must already use the C locale, which the module does not change.

Each private 32/128 KiB corpus contains packed, variable-length log records with IDs, users, statuses and byte counts. Three compiled POSIX extended expressions validate the schema, select warning/failure rows, and select failures. Every successful transaction makes exactly 64 real `regexec` calls, with deterministic varying rows and expressions across requests. Valid records, unrelated notes and valid-prefix/trailing-field negatives are mixed. No pointers, addresses, cache indices, alignment choices or replay tables enter the selection. All five actual match captures contribute content and boundaries to results. Final expected totals use generator-known classes and field boundaries, never prior observed results, and whole-corpus/descriptor integrity covers unqueried bytes.

`preparation-001/manifest.json` records a passing gate. The C tests exercise ten size/seed combinations for 37 requests each, allocation failures, three actual invalid-pattern compilation failures, execution errors after real libc calls, malformed captures, corpus/descriptor corruption, invalid inputs, locale refusal, cleanup accounting and a real fork with private inherited regex state. Separately, eight production-driver cases run 17 requests each under ASAN/UBSAN; an independent Python field parser reconstructs expected results from dumped record bytes without consulting generated C oracle metadata. Seven oracle tests also reject modified records/results/counts, missing requests and missing completion. Host libc is glibc 2.31. The libc DSO itself is uninstrumented; LSan is disabled, and allocation/compile/free accounting does not prove absence of internal library leaks.

The RV64 functional ELF is `preparation-001/regex-functional.riscv`, SHA256 `5276532f68e45c3ab97d2cdbc97424b5506f1352ff14d29d0b993857f6e183ca`. It was only cross-linked. Static assertions check RV64 LP64D, glibc 2.37 public regex layouts/flags; all versioned imports resolve in libc/loader extracted from accepted CPIO SHA256 `e2f7dbc4d02d0ae99bb66832fe94b4882e19d7c95acd2cc0521299ff6aa73f50`. Sysroot and accepted runtime allocated sections match, and real `regcomp`, `regexec`, `regfree` imports are `GLIBC_2.27`. Exact commands, source snapshots, accepted headers and section hashes are retained. No fresh source authentication or RV64 execution is implied.

Corpus size excludes descriptors (about 11.6/46.5 KiB here), opaque compiled/lazy libc allocations, allocator overhead, stack and code. Later integration must charge initialization, all three `regcomp` calls, request execution, final oracle/integrity checks and `regfree`/free in complete-cell costs, and measure actual resource demand. The frozen benchmark `65adf577…` and `resume_workload.h` were hash-checked unchanged; no Makefile, transport, old regex preparation, RTL or board operation was changed. The standalone driver has no scheduling/timing/control loop and is not a new benchmark admission.

Recheck closed evidence with `python3 -B research/retained29-regex-20261121/verify.py`; run oracle failure tests from this directory with `python3 -B -m unittest test_oracle`. `prepare.py` creates a fresh numbered directory for a new host/link gate and never executes its RV64 output.

Raw compiler/readelf/version output is preserved byte-for-byte, including tool-produced trailing whitespace and final blank lines. New source and documentation pass the whitespace check with those raw outputs excluded.
