This experiment tests runtime admission policies over the existing physical instruction replay store. It is a functional capacity control for separating retention/admission from advisory prefetch; it does not establish a Linux speedup, extra guaranteed unique capacity, or FPGA acceptance.

The frozen RTL is BlackParrot commit `2958cd72137d195537b2c86ad11537ea9cd6388e`, branch `experiment/first-demand-retention-policy`, in `/home/coyang/bp-linux-retention-policy`, based on `ffc9bd7641bc1d9b3df6cf530f3a432db3ebae57`. The parent checkout initially retained the demand-copy baseline; the root policy checkpoint now pins this exact new revision after the full-core gates. Nested Git worktrees match the recorded basejump_stl, HardFloat, and bedrock gitlinks; there are no common aviary schema additions.

The hypothesis comes from the prior first-unique predictor evidence (RL013) and the accepted full-core demand-RR engagement audit: captured copies published correctly but produced no side-only fetches. Retaining early completed demand lines could preserve them after L1 replacement without a static address table. Whether that improves complete application execution remains an open experiment; early kernel/poll/setup fetches and bank imbalance may consume this capacity.

CSR `0x5c1` is global uniprocessor I-cache state, not context-saved state. S/M writes retire before issuing a command; generic supervisor-CSR decoding rejects U reads and writes. Readback bit63 reports replay-store capability, bits1:0 the mode, bit2 a sticky completed-demand publication, and bits31:16 a saturating count of consumed side-only I-cache fetch responses. These responses are not architectural retired instructions or cache lines. Remaining bits are zero. Every policy write clears diagnostics and cancels pending demand capture/token, but preserves stored validity. Ordinary accepted fence.i invalidates stored validity and queued publication; it preserves mode and diagnostics. Software writes policy then uses fence.i to begin a fresh admission epoch.

Modes are 0=legacy advisory-only admission, 1=ordinary cached demand RR admission, and 2=first-completed demand admission. Mode3 is reserved and coerces to0. Mode2 protects complete entries within the existing selected bank, matching tags continue assembly, and incomplete/aborted or unallocated slots remain reusable. Once a bank is full of completed entries, a new ordinary line is dropped even if another bank has room. Explicit advisory replay keeps legacy replacement permission in all modes. Mode0 can still serve existing valid side copies until the next ordinary invalidation.

The same existing 32-entry store, registered response stage, word banks, physical tags and beat masks serve all policies. Relative to the demand-capture control, runtime policy adds 2+1+16 control/diagnostic state bits. It adds no SRAM read, 512-bit data stage, or memory request, and leaves ordinary SRAM yumi arbitration unchanged. Capability depends on existing replay_buffer_p. The prior experimental compile-enable parameter/macro is deliberately superseded in this isolated branch; reset mode 0 preserves the accepted default admission behavior.
