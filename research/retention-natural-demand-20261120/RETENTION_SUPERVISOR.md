This root-owned supervisor supplies the receipt producer required by the frozen retention completion gate. It runs one canonical reservation and records its actual subprocess return; it adds no target flag, statistical selection, retry, recovery or board command.

`retention_supervisor.py LABEL` validates the frozen operations/table/validator and artifact set, requires the bounded old-hardware ABSENT proof, and checks the entire preceding completed prefix before selecting the exact next argv. Each label obtains an atomic local claim before launch. The unchanged serialized wrapper remains the sole owner of the common FPGA reservation, board-side program lock, staging and recovery. No retention launch is permitted until the current diagnostic has finished and the bounded compatibility proof is accepted.

The supervisor writes the ending receipt only after the actual wrapper returns. A complete receipt requires exit0, complete/released session metadata and unchanged source/artifact bindings; every exception or nonzero return remains failed. The receipt records the supervisor PID/start ticks, enclosing UTC times, exact argv, source hashes, producer binding and compatibility proof. Root must wait for the supervisor to disappear before using the offline prefix gate. A missing, partial or failed receipt stops continuation. A killed parent can leave its serialized child live, so observe the actual child/lock before recovery; never infer a released board solely from the parent PID.

This is a separate root-reviewed addition to the earlier operations task, which deliberately supplied no producer. Its optional producer/proof receipt fields remain reviewed acquisition provenance; the frozen prefix gate independently verifies its required operations/table/validator fields and complete session/guest evidence. It does not retrospectively prove arbitrary handwritten receipt history. All sources and launch records must be retained, and claims/receipts are never silently reused.

`supervisor-proof.json` binds source, tests and the independent read-only review. Seven host tests invoke local child processes only: actual return capture, nonzero-with-complete-manifest rejection, missing/incomplete manifest rejection, duplicate-claim refusal before execution, changed-dependency refusal and missing compatibility-proof refusal. No physical command runs in those tests. The first fixture used an already-existing output directory and was correctly refused before child launch; the fixture was corrected to model a new session directory.
