This change repairs missing retained-buffer and response-delay Verilog defines in the FPGA build flow. It preserves the rejected first fit attempt and proves the corrected configuration in actual packaged nested RTL and launched Vivado child synthesis. It does not establish full-design FPGA capacity or timing.

`vivado-utils.tcl` now applies a validated six-name allowlist in source-project creation, IP-edit/customization and final-project creation. Conflicting definitions, malformed or partial retention settings, and missing property readback fail before build proceeds. Existing context-configuration selection remains unchanged.

Project defines are explicitly reinjected; the IP package is not self-contained configuration. AMD UG1118 documents that project Verilog defines should instead be placed in HDL headers for portable packages ([2024.2 supported inputs](https://docs.amd.com/r/2024.2-English/ug1118-vivado-creating-packaging-custom-ip/Supported-IP-Packager-Inputs)). This repository uses the checked flat BD flow with `synth_checkpoint_mode None`; a future independent OOC flow needs its own propagation gate.

Closed probe03 uses the same create-design/package/import-files/customize/new-consumer/launch-runs helpers as the real build. All192 synthesized output bits independently decode to `{1,1280,1280,256,1,200}`. Its actual child Tcl carries all six defines before synthesis. A fresh consumer of the same package with all experiment settings absent decodes to defaults `{0,64,64,64,0,0}`, demonstrating that package availability alone does not configure retention. Six parser refusal tests and the Tcl allowlist/conflict/readback tests pass.

Probe01 failed before packaging because its fixture incorrectly used a SystemVerilog module-reference top; the real design uses Verilog `top.v`. Corrected probe02 completed direct synthesis, and fresh probe03 strengthens acceptance to launched child contexts and the negative control. Failed and successful exact inputs, transcripts and output netlists are archived under `closed03/`; fullcore simulation, actual feature elaboration and a routed implementation remain separate gates.
