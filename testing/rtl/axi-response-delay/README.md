This isolated response-delay shim is an experimental control for later shared-memory-latency sensitivity tests. It preserves opaque AXI R and B streams and adds programmable minimum response age; it is not a DRAM model, load-ready measurement or optimization. No top-level placement, full-core behavior, routed resource/timing feasibility or physical calibration is established by these unit tests.

The two new RTL files are `cosim/black-parrot-example/v/bp_axi_response_delay.sv` and `bp_axi_response_delay_fifo.sv`. Integration must place one instance on the **common HP0 return path before demand/prefetch response demultiplexing**, so normal I/D traffic, bypass-prefetch IDs and write responses receive the same setting. L1/retained/L2 hits that never reach HP0 are outside this path. Root owns that integration and the measured clock/path audit. Baseline and optimized comparisons must retain identical shim hardware/settings and traffic accounting.

`r_v_i/r_ready_o/r_payload_i` denote the incoming response producer; `r_v_o/r_ready_i/r_payload_o` denote its consumer. B has the same interface. Default opaque widths are R73 and B8 (sufficient for64-bit data,6-bit ID,2-bit response and RLAST); integration may choose another consistent packing/width. The shim never parses, changes, drops or reorders payload fields. R and B have independent queues and can progress together.

At delay0, valid, payload and ready are direct combinational assignments. No response queue accepts data in that mode, and no response-clock stage is introduced. This is cycle/handshake identity, not a claim that the physical mux has zero propagation delay. With N>0, every accepted input beat records the current response-clock counter and becomes eligible no earlier than N cycles later. Head eligibility is latched so VALID/data remain stable under head backpressure, including counter wrap. Unsigned enqueue-age subtraction avoids the premature return caused by comparing against a wrapped future deadline.

Each FIFO has512 actual occupied slots by default, including head/next entries mirrored in small registers. It uses one synchronous-write/registered-read RAM with no array reset. The next-next word is prefetched while the head is consumed; small write-forwarding registers cover one/two-entry cases without RAM collisions. This sustains one response beat per clock after fill, rather than charging N separately to each serial burst word. Depth may be non-power-of-two. Backpressure can lengthen actual service beyond the minimum age; exact+N timing checks refer to unsaturated, freely draining streams. Queueing is not CPU stall time or a DRAM attribution.

The default maximum configurable delay is384 and counter width32. Configuration requires both response queues empty, no incoming response VALID and `cfg_safe_i` asserted by external full-transaction quiescence (including outstanding AR/AW work). Response queues alone cannot prove that condition. A one-cycle `cfg_v_i` command while unsafe/busy or out of range is rejected without changing level or data. `cfg_accepted_o` pulses on success; `cfg_error_o` is sticky until reset or a successful configuration. There is no automatic retry or deferred command. `active_delay_o`, `idle_o`, cycle counter, queue occupancies/full flags and saturating32-bit full-input-stall counters are exposed. Accepted configuration resets the stall counters, not the free-running clock counter or RAM contents.

Full queues backpressure incoming VALID until space or a same-edge output transfer is available. Stall telemetry counts positive-delay cycles with incoming VALID and input not ready, not native downstream backpressure or attributed application stalls. Reset flushes queued responses as an AXI transaction-domain reset; it is not a live-data draining/configuration mechanism. Tests explicitly account for the three R/B entries intentionally abandoned by reset, and require conservation of every other accepted response.

It checks128 unclocked native-wire input combinations; full8-beat64-byte burst first/final shifts of exactly1/2/8/40/200/384 clocks, continuous one-beat output spacing and equal B shifts;1024 R plus1024 B transfers per random-ready setting at N0 and N40; mixed IDs, interleaved bursts, response codes/RLAST/data preservation; full512-slot backpressure and exact stall telemetry; busy/unsafe/invalid configuration rejection; clean drain/reconfiguration and queued reset behavior. Accepted/offered times are shim-response-clock observations, not AR-to-data or instruction/load completion times.

The32-bit tests seed the counter near wrap: for example N40 shifts input cycle4294967283 to output cycle27, with a separately tracked64-bit test-clock delta40. Short-counter tests exercise the parameterized wrap logic, not physical clock calibration.
