This gate checks the new shared retained-full-line backend in isolation, with actual 64-byte payload slots for both I and D. It verifies capacity, clock independence, publication and coherence/ownership contracts; it does not establish routed BRAM inference, fit, application usefulness or performance. Ordinary L1 geometry is unchanged, and root owns integrated cache/UCE, full-core and FPGA gates.

`import/black-parrot/bp_common/src/v/bp_retained_line_store.sv` stores all configured I/D payload in one true-dual-port 64-bit-word RAM and all physical tags in one synchronous tag RAM. Port0 belongs to I, port1 to D; their clocks may differ. Physical RAM address partitions are disjoint and asserted on every access. Tags are scanned by indexed set/way; a hit assembles eight synchronous word reads into one constant-size response register per lane. There is no capacity-wide CAM or asynchronous full-line payload mux. `ram_style="block"` expresses intended implementation; only actual synthesis/routing can establish its realization or practical maximum.

Parameters are `paddr_width_p`, power-of-two `sets_p` (default64), `i_lines_p`, `d_lines_p` and `epoch_width_p` (default8). Line counts may differ, be non-power-of-two, include a partial final way, or be zero. For example1320 lines have20 full64-set ways plus40 slots in the final way. I/D share RAM allocation rather than rounding each partition to a separate memory depth. An address table, UCE transaction slot or transient 512-bit assembly register is not counted as retained payload capacity.

| Packed two-lane interface, lane0 I / lane1 D | Contract |
|---|---|
|`clk_i`, `reset_i`|Each lane's own cache/UCE clock; synchronous reset. No cross-domain handshake.|
|`lookup_v_i`, `lookup_ready_o`, `lookup_addr_i`|Physical byte address, one outstanding request per lane. Lookup has priority over insertion at idle.|
|`resp_v_o`, `resp_ready_i`, `resp_hit_o`, `resp_data_o`|Exactly one response per accepted lookup, held until ready. Eight64-bit words in ascending physical-address order.|
|`insert_v_i`, `insert_ready_o`, `insert_addr_i`, `insert_data_i`|Atomic complete aligned64-byte line; client assembles and validates all beats before acceptance. Optional captures may be dropped by the client when not ready.|
|`insert_replace_i`|Capture first invalid entry, refresh matching tag, or RR-replace when full. If false, an unmatched full set refuses publication.|
|`insert_cancel_i`|Cancels an already accepted pending insertion, including after partial payload writes.|
|`insert_done_o`, `insert_published_o`|One-cycle pulses in the lane's own clock domain for every accepted insertion's terminal outcome. Published implies done and occurs only with the final payload write plus valid-tag publication.|
|`clear_i`, `invalidate_v_i`, `invalidate_addr_i`|Clear the partition, or conservatively invalidate the physical backend set. They suppress pending hits/publication immediately.|
|`busy_o`, `epoch_wrap_o`|Outstanding work/response, and epoch-wrap event.|

Permissions, PMA/MMU checks, normal-L1 hit/dirty filtering, accepted store/AMO/SC mutation addresses, fill generation/abort rules and runtime enable/policy control belong to clients. Disabling lookups is distinct from enabling demand capture. No ordinary L1 refill handshake may wait on optional capture. An accepted backend lookup must be drained even when its architectural client is canceled; the client can poison that ownership token.

Coherence is deliberately conservative: an accepted mutation advances an8-bit epoch for that backend set, killing **all** retained lines in the set, including unrelated clean tags. It also cancels a pending insertion or query in that set. An epoch wrap clears all tag validity in that partition before any old epoch can be reused. Clear/reset sweep tag RAM only, never payload RAM; lookups/inserts are blocked during the finite sweep. New mutations during an already-invalidating sweep need no extra work. Cold startup and wrap/clear sweep latency and collateral loss are real costs to price, not evidence of useful unique capacity.

Response valid remains owned until its handshake. **Coherence may revoke a queued hit to a miss while stalled**; consumers may use hit/data only on the handshake. This is an explicit exception to ordinary held-data stability. Absent clear/invalidation, response hit/data remain stable. Clear/invalidation never silently discard an accepted lookup: it gets a forced miss, including during a sweep. Inserts invalidate the selected tag before writing payload; after eight accepted writes, valid publication is atomic. Canceled partial contents stay invisible.
