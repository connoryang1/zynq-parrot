This isolated prototype tests whether retained-store metadata can use distributed RAM while preserving every client cycle, full-line payload and coherence decision of exact SP BP `d766d42cdf04ee43ca1e915fb9da06f5cc117dde` (top `11ca59a27`). It changes neither payload/tag BRAM, retained geometry, epoch width, policy nor ordinary L1 geometry. It is not an adopted optimization, routed image or application speedup result.

D epochs use a reset-free single-write array only when that partition has at least one line per configured set. RR uses a separate reset-free single-write array at supported depths on each lane. Existing tag-clear cycles concurrently zero metadata at the low set bits of the clear slot; the tag sweep already visits every set before accepting work. Smaller/disabled partitions keep the original all-set FF reset/clear behavior, including epoch wrap of unused sets and the original clear duration. I epochs keep the original FF implementation so production I invalidation tied to zero can prune them. `ram_style="distributed"` expresses an inference intent, not measured implementation evidence.

Epoch invalidation has its own asynchronous read; accepted-insert capture and active tag comparison share a second read because those uses occupy different FSM phases. Epoch and RR remain separate writers because an unrelated invalidation and successful last-beat insert may write both on the same edge. Clear/wrap suppresses normal writes, cancels publication, revokes queued hits and drains accepted lookups exactly as before. Held clear/restart and invalidations during clear retain the old FSM priorities. No RAM reset, initialization state, extra busy cycle or payload staging was added.

`BP_RETAINED_METADATA_VERIFY` adds only a simulation initialization bitmap assertion. It is absent from normal implementation builds. The test wrapper deliberately fills both designs' metadata, tag RAM and payload RAM with nonzero values before reset. The miter compares all ready/busy/response/insert/wrap outputs, every hit's complete 512-bit payload, FSM/slot/word progress and all active RAM port address/control/write-data signals after each model evaluation. Its reference snapshot is byte-identical d766 (`aa36581844c5563f77bcc12f531776a4c858b1470a202d8f8394c7a02a7f8ea7`); compilation renames only that module identifier.

The directed driver derives from the frozen retained-line-geometry driver and preserves full-slot/full-payload checks, high physical tags, replace/no-replace, parallel lanes, abort/cancel, in-flight/queued-hit invalidation, fence/clear and wrap checks where geometry permits. New checks cover reset held/restarted with nonzero storage, clear held/restarted at the last slot, invalidation during clear, unrelated invalidation plus final publication, lookup acceptance plus new-set invalidation and unused-set wrap in shallow partitions. Each clock mode also runs 80,000 ticks of deterministic randomized reset/clear/mutation/cancel/offer/response-backpressure stimuli. Small geometries omit inapplicable distinct-set checks; they do not claim those cases as covered.

`matrix.py` runs sequentially, preserves failures, enforces at least 3 GiB free plus a bounded allocation and performs no automatic retry. Its 20 geometries cover the frozen capacity range through 1536 lines/side, asymmetric partial ways, I-only/D-only/zero partitions, sets 1/2/4/64/256, and the actual 1280/256/epoch8 configuration. Each uses inverted clocks and independent 5/7-period clocks. Build artifacts and closed FSTs remain outside Git; small source-bound manifests and logs are retained here. No Vivado, full-core, application or board operation is performed by these scripts.

Reproduce with `python3 testing/rtl/retained-metadata/matrix.py --build-root /tmp/NEW-retained-metadata-matrix --evidence testing/rtl/retained-metadata/evidence/NEW-matrix`. Outputs must be fresh. Existing gates, originals and failed setup attempts are retained rather than overwritten. A successful component miter cannot prove inference, LUT savings, timing, routing or Linux benefit; actual hierarchy/inference/routed evidence is required before adoption.
