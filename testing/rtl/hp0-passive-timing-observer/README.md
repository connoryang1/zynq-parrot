This is a standalone passive prototype for measuring physical AXI read windows. It has no AXI outputs, address filters or connection to a production top, image, CSR or benchmark. Actual BRAM mapping, area, timing, whole-system behavior and deployment remain unverified; a later ROOT-admitted diagnostic image is separate from COST images.

`hp0_passive_read_timing_observer.sv` samples one rising AXI clock edge. ARVALID/ARREADY starts a request; first/full **offered** means the first RVALID / first RVALID+RLAST sample, and **accepted** adds RREADY. Only isolated reads produce valid metrics. An extra AR before prior reads drain invalidates the original window, increments ignored-AR coverage for the extra request, and stops attributing its responses; the invalid window is stored at drain. Completing RLAST plus new AR on one edge ends the old window and starts the new one. No favorable subset or target-address selection exists.

Read AR→accepted-RLAST and independent write AW→B / accepted-WLAST→B ledgers run through freeze. W-before-AW, partial W bursts and same-cycle transitions are supported without false underflow. Write overlap is an informational observation of pending/accepted AW/W/B activity, **not** evidence of exclusive memory service or a cause of latency. The W channel has no WID and assumes a noninterleaved write-data stream. This is not a complete AXI checker, global-memory drain proof, data-integrity checker or I/D attribution mechanism.

Counters and age saturate on overflow. Ledger underflow/overflow sets sticky protocol errors, poisons drain knowledge and blocks new valid captures/freeze until reset. Isolated wrong RID, RRESP error (SLVERR/DECERR), LEN/RLAST mismatch, unrepresentable address/ID, age or per-record count overflow invalidate the record. EXOKAY remains successful and is recorded. An independent age counter makes short reads across a free-running cycle rollover valid; a rollover flag is informational, while an overlong age never wraps into a fast valid sample. Reset must accompany a quiescent/reset AXI boundary; resetting observation alone cannot reconstruct previously unobserved requests.

The ring holds the latest16 windows, including invalid ones. `record_count_o` counts occupied entries and `valid_count_o` counts their valid entries; `record_total_o`, accepted `ar_count_o`, `ignored_ar_count_o`, per-record AR sequence and write pointer expose loss/gaps/overwrite. Statistics saturate with a sticky error. After16 records, the next write-pointer slot is the oldest entry. A host must require complete expected sequence/coverage and inspect **every** target record, not pick valid-looking survivors. A window with more than16 required records needs a separately designed acquisition protocol; this prototype does not pretend the ring retains its overwritten history.

Freeze is sticky until reset. A pending freeze permits existing reads/writes to drain, rejects/counts new ARs and flags them; actual post-freeze read/write activity is sticky and never changes the ring. Freeze cannot assert on a record-write edge. A later `rd_v_i && rd_ready_o` accepts the host's7-bit index (entry[6:3], word[2:0]); one synchronous RAM-read stage precedes a held `rd_resp_v_o`, exact index echo and data. The response stays stable until `rd_resp_ready_i`. Thus freeze+final-RLAST/read collision cannot return the old record. Unoccupied entries read as zero; RAM payload is not reset. Only small ring index/quality/control state is reset.

`version_o` is0x48503001. Default widths are address32, ID6, free cycle32, age16, per-record/ledger count16 and statistics/sequence32. Wider addresses/IDs are accepted as inputs up to64 bits but cannot become valid if they do not fit the fixed record fields. Smaller counter/age widths are verification controls, not workload settings.

| Word | Fixed32-bit format |
| --- | --- |
|0|Raw AR address low32; high nonzero address bits invalidate|
|1|AR sample's free-running cycle (zero-extended when shortened)|
|2|First offered latency[15:0], first accepted latency[31:16]|
|3|Full offered latency[15:0], full accepted latency[31:16]|
|4|ID[5:0], LEN[13:6], SIZE[16:14], BURST[18:17], valid[19], seen first-offer/first-accept/full-offer/full-accept[23:20], OR of observed RRESP[25:24], reserved[27:26], format1[31:28]|
|5|Accepted beat count[15:0], RVALID&&!RREADY stall cycles[31:16]|
|6|Flags[15:0], peak total read outstanding[31:16]|
|7|Accepted-AR sequence, starting at1; overflow saturates and invalidates|

Flags0..13 are read overlap, wrong RID, RRESP error, LEN mismatch, age overflow, beat overflow, stall overflow, cycle rollover, address/ID truncation, read-ledger failure, write overlap, write-ledger failure, AR during freeze request, and statistics/sequence overflow. Only flags7/10 are informational. Missing latencies are0xffff with their seen bit clear; invalid records' partial metrics must not be interpreted. Peak/count values saturate on overflow. Sticky `errors_o` bits0..8 are read underflow/overflow, write underflow/overflow, statistics overflow, traffic after freeze (also new AR after request), wrong isolated RID, RRESP error, LEN mismatch. `status_o` bits0..9 are frozen, freeze pending, capture active, read pending, held response, partial W, ring full, read ledger poisoned, write ledger poisoned, any free-cycle rollover since reset; upper bits are zero.
