This directory preserves a directed full-model test of how intervening data traffic affects four completed physical data prefetches. The two passing runs use the accepted data RTL and the same 4 KiB interference stream; the second reissues the hints after that stream. Their waveforms show a cache-retention mechanism, not a measured Linux or application speedup.

# Four-line L2 retention and late reissue

The source worktree was `/dev/shm/zp-linux-l2-tag-probe`, with top-level base `c8157859` and BlackParrot `be1967914`. Both passes used the full two-bank `cosim/black-parrot-example/verilator` model, `DEFINES='BP_ZYNQ_PREFETCH_TWO_BANKS BP_AXI_MEM_PIPELINED'`, `NUM_THREADS=2 NUM_CONTEXTS=10`, `TRACE=1`, and `TARGET_RUNTIME_MS=1000`. Each variant followed a completed `make -C testing clean`; the early variant's guest and host reached PASS, then the late variant's guest and host reached PASS. The exact source files and guest ELFs are retained here, and the full-model FSTs are compressed with xz.

For each variant, copy its retained C source to `testing/mt_physical_preview_gap_test.c` in an isolated worktree at the recorded revisions, add that test to the testing Makefile with the physical-preview `SIM_DEFINES`, and register its exact PASS marker in `testing/check_run.py`. Run clean to completion, then run `env DEFINES='BP_ZYNQ_PREFETCH_TWO_BANKS BP_AXI_MEM_PIPELINED' make -C testing run-mt_physical_preview_gap_test SIM_DIR="$PWD/cosim/black-parrot-example/verilator" NUM_THREADS=2 NUM_CONTEXTS=10 TRACE=1 TARGET_RUNTIME_MS=1000`. The observed result requires both guest `CORE PASS` and host `BSG PASS`; archive each closed `dump.fst` before the next clean run.

The target is four 64-byte lines beginning at `0x80008000`; the interference array is 64 distinct lines beginning at `0x80009000`. In the early run, all four hints complete, then all 64 interference lines generate accepted L2 requests and DMA reads. Each later target demand generates a new DMA read. In the late run, the same early hints and traffic occur, followed by four more completed target hints; these cause four DMA reads before demand, while the four demands cause zero target DMA reads. The late run waits for publication and therefore demonstrates residency restoration, not hidden latency.

`gap64-target-events.txt` and `gap64-late-target-events.txt` were extracted from the closed FSTs with the already maintained `logs/l2-physical-preview-20261028/extract_target_l2.py --target 0x80008000`. `gap64-interference-events.txt` used the included `extract_gap_l2.py --target 0x80009000`, which changes only the target range from four to 64 lines. The initial lines in that transcript include program-load traffic; filter to events after the completed target hints to count the 64 runtime interference reads. The uncompressed FST SHA-256 values are `12c2853669d1b0bde83a77c402d57a919efae93d988633520127d3bdac283e93` (early) and `32d49d5b809110487a1013583ffbe07f24f33f8413004d9495e67a66c0e4513d` (late); the committed compressed files and ELFs can be checked directly with `sha256sum`.

`full-model-invalid.log.xz` preserves the failed TAGLV/TAGLA known-present attempt; the two passing run logs are also compressed with xz to keep their raw whitespace intact. The returned tag values were outside the valid/lock encoding, so software management reads are not accepted as a Linux L2-residency probe. The isolated source worktree also retains failed-build and timeout details in `logs/l2-tag-probe-20261030/README.md`; those runs are not performance evidence.
