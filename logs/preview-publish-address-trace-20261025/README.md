This directory records simulation validation for an opt-in address trace of completed D-cache previews. The trace is intended to show whether a scheduler-published response names the same physical segment as a later target load. It does not yet establish Linux board behavior or a performance gain.

BlackParrot `da2b44781` adds CSR `0x805` bit 2. Writing `6` clears the histories and enables publication recording while demand recording remains disarmed; writing `5` later arms demand recording without clearing publication records. The mode reserves D-history indices 248–255 for eight final-response records while retaining indices 0–247 for ordinary D misses. A publication record is `{cycle[31:0], 2'b11, paddr[33:4]}` and is selected through CSR `0x806` with D source bit 8 and index `248+i`; CSR `0x805` bits 56:53 report record count, bit 57 reports publication overflow or a same-cycle D-miss/write collision, and bit 58 reports the selected mode. When bit 2 is off, the original 256 D-miss records and their format remain available.

The accepted control used separate `make -C testing clean` and `make -C cosim/black-parrot-minimal-example/verilator clean`, then `TMPDIR=/dev/shm/zp-preview-address-compiler-tmp make -C testing run-mt_preview_side_buffer_pressure_test NUM_THREADS=2 NUM_CONTEXTS=4 TRACE=1 VERILATOR_BUILD_JOBS=8 TARGET_RUNTIME_MS=80`.
