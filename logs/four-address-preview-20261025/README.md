This directory preserves physical Linux measurements of a four-address scheduler data preview. The experiment keeps the qualified FPGA bitstream fixed and changes only the per-task Linux descriptor and the benchmark's target-page access pattern. It separates target demand-miss reduction from whole-handoff timing, and retains unsuccessful diagnostic runs so their limits are visible.

The FPGA package and bitstream are the RL-075 preview RTL, SHA-256 `858cba88472432f157efab225baed74498f8740302fb5054dcd01aa93e42300b` and `5f1a725e215b7e46bc2c787df0b2820f536ec744b0ada4ada886483c942f2367`. The kernel adds four validated addresses to each task's same-mm descriptor, emits up to four advisory ORI hints in its existing `context_switch()` hook, and clears the descriptor on exec/fork. The workload places four 64-byte target lines in one page, uses distinct stale lines, records accepted D-cache demand misses around each of the four loads with CSR `0x805`, and reads saved physical addresses through CSRs `0x806`/`0x807` outside the timed interval. Source checkpoints are `dea9dc58` (four-address descriptor), `114764b1` (eight eviction pages), and `72f964a8` (non-target target-page DTLB probe), all on isolated experiment branches.

The first ten-page run (`board-guest.log`, SHA-256 `2474129862c04f1d4cf4b81593191586c2cc9fc3b3a5712c5d7e4791f06382d6`) printed guest PASS and returned runner zero, but one trial overflowed the recorder, so its strict analysis failed. The corrected ten-page trace NBF SHA-256 `829d381c9889b73008a407b2dcd7084fa0c224cd773f4b5ffd92af01e7498f65` arms/clears immediately before the four loads and passed all 48 rows (`board-guest-trace.log`, SHA-256 `71f480ff83a621e4bfb960040ada13d39e385f1a8e130b710988d68c95c43380`). Its first load usually caused an accepted request to the same physical line `0x82b21500`, followed by four consecutive target-line addresses. This pattern is consistent with a page-table walk on a missing target DTLB entry, but that address has not been independently identified as a PTE. Exact hints eliminated all four target demand misses in only 3 of 16 trials.

The eight-page variant keeps target and stale lines cold while using two fewer DTLB entries. Its NBF SHA-256 is `7c0a09a9d8eb8b8e2afdc6887689823bda478e720ed9677de01b777d2f488a60`. Two board runs (`board-guest-eight.log` / `board-guest-eight-repeat.log`, SHA-256 `61217055b318d26a5d6cd573d22b52bed91482d42a3059329f10e0bf5d80d282` / `551732959b885380962e49ae98c11a79a488f7155cdd62511ab80769adba8e40`) passed 48 balanced trials. Exact eliminated all four misses in 5/16 and 4/16 trials. Off and stale each missed all four target lines in every ordinary trial. Repeat trial 8 was interrupted during the third off-mode load: that CSR interval captured 64 accepted requests to unrelated physical addresses. Excluding its three-trial block from paired timing changes the repeat's exact-minus-off roundtrip median to +3,466 cycles; the first run was -7,588.5 cycles. Thus a whole-handoff speedup is not established.

The final variant touches a *different* target-page line after the eight-page data eviction and before wakeup. Its static benchmark, embedded rootfs, kernel Image, and final NBF SHA-256 values are `c2296089e2ea98d23a4021716c961415e60d757db0315320605980e1e56382be`, `792724b940731ae1b78be695ce0809faba3dbef6b7551aa4953fa13bab7d06b1`, `cb6aebcc4a11c5e4a5c02843ef31fe70079eac9b18526eb4494d842f44117094`, and `e09bd56d86516e1406832727944e054377b0e3e26feed350e8b1ccbc6409af74`. The retained `linux-preview-four-probe.nbf.xz` decompresses to that exact NBF; compressed SHA-256 is `77730a6a44b31bf52da7aadebe88b4d9e6f2aaa080307522045446ae1f9fe2b3`. Both fully recovered board runs returned `BSG PASS`/runner exit zero, printed `SCHED_PREVIEW PASS`, and passed the strict 48-row analyzer. Raw logs `board-guest-probe.log` / `board-guest-probe-repeat.log` have SHA-256 `f7d630b0396d8a988898ef49d2cfa6db0264dfa4aa7ab7baf04432ee3d5ec55a` / `6e1f10f9fd5571c6fe8134cdcf06cfc619c79f213421dddd2a4114ba6c44ca8b`.

In both final runs, off/stale each had 64/64 target demand misses, while exact had 4/64: all four target lines were warm in 15 of 16 exact trials. The same exact trial 40 missed all four in both runs; it had a long switch-entry interval, but an intervening scheduler task or skipped same-mm hook is only a hypothesis. Paired exact-minus-off median four-load intervals were -189.5 and -197 cycles, while paired whole-roundtrip medians were +415.5 and +2,308.5 cycles. Warming four lines is therefore repeatable and locally useful, but it has not accelerated the complete futex handoff.

Build and measurement guardrails: the default `riscv64-unknown-linux-gnu-gcc` was absent, so compile the benchmark with the explicit Buildroot `riscv64-linux-gcc`. An initial OpenSBI invocation used ineffective `FW_PAYLOAD_PATH`/`FW_FDT_PATH` variables and reported “Nothing to be done”; a forced rebuild with the SDK Makefile's `PAYLOAD_PATH`, `PLATFORM_FDT_PATH`, `FW_PAYLOAD=y`, and hart-count flags succeeded, followed by an exact one-copy kernel/DTB check. The timer patch helper rejected the corrected trace image because it found a second four-byte FDT magic in the kernel; its following size was 776,847,033 bytes, so it was not a valid DTB. The final NBF was made by verifying the exact 46 MiB/8 MHz DTB at `0x80016000`, a single selector write, DRAM bounds, and final opcode, then changing only that selector line from 1 to 2. Analyze only the single raw guest log for each run; runner transcripts repeat guest lines.

Source checkpoint `6254f335` adds a per-task count increment immediately after the four hint instructions and a diagnostic `PR_BP_PREVIEW_GET_COUNT` query. The final hook-count NBF SHA-256 is `e5e5eabdf0111ad2d890bdcc0edccd5e0aa534e49e803365a65e3a877d9c576e`. Two further board runs passed 48 balanced trials and runner exit zero; raw guest logs `board-guest-hook-count.log` / `board-guest-hook-count-repeat.log` have SHA-256 `482d26c058daf3e103e3cb191e02bde48b7d3f36251e4d9ce05f50658efb6dfb` / `9c01764a6673885b24f7696787455d45bf77db3771c20c2a573f21c30ab263d3`. Off/stale each still had 64/64 target misses; exact had 0/64 and 4/64. The failed exact trial 2 in the repeat had a hook-count increment of one but all four target misses, so hook execution alone does not ensure useful hardware delivery. Trial 40 had a hook-count increment and zero target misses in both instrumented runs, showing its failure in the earlier image was not a permanent address or set conflict. Some stale trials had no hook increment and several trials had two increments, confirming scheduling-path variation. Paired exact-minus-off median four-load intervals were -166.5/-165 cycles; whole-roundtrip medians were -1,727.5/-11,012 cycles, while stale also had negative roundtrip medians. These instrumented timing results do not establish a causal whole-switch gain.
