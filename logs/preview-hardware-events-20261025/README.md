This directory records validation of hardware counters for Linux scheduler data-preview hints. The counters distinguish a translated physical hint, preview-queue admission, memory issue, and a complete side-buffer response. Results here are diagnostic until a matched Linux workload and routed FPGA image have been verified.

The first clean traced `mt_cache_miss_trace_test` rebuild failed during generated C++ compilation because GCC wrote temporary assembly to `/tmp`, where the root filesystem had only 13 MiB available. `testing/logs/verilator_build.log` records `No space left on device` in several `Trace__*__Slow.cpp` compilations; no simulator result from that build is valid. The guardrail is to clean the failed model and set `TMPDIR` to a directory on `/dev/shm` before rebuilding.

With `TMPDIR=/dev/shm/zp-preview-compiler-tmp`, a separate clean traced build and `make -C testing run-mt_cache_miss_trace_test TRACE=1 VERILATOR_BUILD_JOBS=8` passed its specific guest marker, `CORE PASS`, and `BSG PASS`. The `mt_smode_prefetch_sum_test` then used that model with a freshly built test program and passed the same gates; it reported physical/admitted/issued/published counts of `1/1/1/1` for one permitted S-mode hint, while a second hint denied by `SUM` added no event. The closed FST, exact NBF, and full run log are retained here for each test; SHA-256 values for the S-mode files are `cd1ed94008bf46ce462626189ef98c13617e76aada94a18ba9284ecd626e0ff8`, `27f51a14310a231df11e5bd19322f675726362816375ee68272a2e4537e84441`, and `20468afd5f8c9ef755a18f86fcfe061a8a36a799abfae231dd37d6ee3bd9e655`, respectively. These simulator checks validate counter wiring, not Linux coverage or routed timing.
