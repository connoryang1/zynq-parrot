The benchmark must still be run with a booted kernel that contains this patch and the bounded-hint RTL. Its `wake`, `entry`, `load`, and `roundtrip` fields are distinct intervals; a faster `load` alone is not a whole-handoff speedup. The current hook is intentionally limited to `prev->mm == next->mm` and a DTLB-hit target address. Page-table generation, pending-hint cancellation, cross-mm translation, and task-footprint learning remain open before a general Linux feature.

The cold-line control has a concrete cache-index basis. This static `prefetch5` configuration inherits a 64-set, eight-way 64-byte D-cache and has one L2 slice with two banks, 16 sets per bank, two ways, and 64-byte lines. The L2 hash uses physical bit 6 for the bank and bits 7–10 for the set; 4 KiB-spaced pages at the same page offset therefore contend for the same bank and set regardless of physical page placement. `prepare_cold_line()` touches the target and stale lines, then reads ten distinct 4 KiB-spaced eviction pages at offsets 0, 64, 128, and 192. That is deliberate pressure beyond both the L1 eight ways and L2 two ways for the target's index. It establishes the benchmark's eviction intent from the RTL geometry; only a hardware trace or counters can prove the target actually misses L2 on a measured trial. The benchmark's 12 user pages also fit within the configured 16-entry 4 KiB DTLB before considering kernel accesses, so scheduler-time DTLB-hit coverage remains an empirical question.

`git diff --cached --check` flags unchanged context lines inside the newly tracked `.patch` file as if they were new source whitespace. The guardrail is to run that Git check on the other staged paths, then run the Linux patch checker and `patch -p1 --dry-run` on the patch itself; both latter checks passed for the exact patch recorded above.
