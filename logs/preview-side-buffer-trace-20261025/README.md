This directory records the side-buffer removal trace experiment for the Linux scheduler preview. It preserves the first bare-metal diagnostic failures and distinguishes a trace-read timing mistake from the cache behavior under investigation.

The first clean `TRACE=1` two-resident/four-context `mt_preview_side_buffer_pressure_test` run failed its new address assertion after the older data and publication checks passed. The closed FST `pressure-first-fail.fst` (SHA-256 `273e025174c753272e414e38daa857ad3252551df17a1cc5267f6f6ba15c083f`) shows three older-slot replacements followed by all four target consumes at physical segments `0x80008000/40/80/c0`. The test's status CSR was read too soon after the fourth load: the next diagnostic transcript reports a removal count of five and records only the first two target consumes, while the waveform shows the count advancing to seven afterward. This is a trace-snapshot timing error; the next test places a short delay before the status read and must verify all four address records without changing the target data path.

Six `nop` instructions before the final status read made the same control report seven events: three older replacements, then four target consumes. The delayed-read test passed with SHA-256 FST/NBF/log `753b57eff6bdacecda90e926f6a7c73cc88015d5eadee182e1d752f1fa932694`, `eb88dc55196d482021070a384471de47a96f60808050fefc879c0d5c9c86e03f`, and `fea99ecd20b82c6299e468f071dd24cc6ac4b114b68eb439614d3d9c89569dd0`. After removing temporary guest printout, a clean test rebuild again passed the test-specific marker, `CORE PASS`, `BSG PASS`, and `VALID RUN`; its closed FST/NBF/log hashes are `99f801233b6f1408645dccaf12a537929020d6fc02b7ad22ec311722f4a68883`, `31c5409579b46a26e9cf937312c9e3ca6f721613b4433da84cb5f077b486fbfd`, and `fbcc7bfa1e9e6984d62d6320bd23e35ab948d9a0e16327833ef1e896bc8a8395`. The serial mode-off `mt_cache_miss_trace_test` on the same rebuilt RTL model also passed with two accepted I misses, one accepted D miss, `CORE PASS`, `BSG PASS`, and `VALID RUN`; its FST/NBF/log hashes are `df43af61fbd152784fd1075cdc356bb13de56a2a41cee3b56e88ce60fd6562c5`, `e30d602e3b857ec99f6248f16390e53ae4ce5cc4ac5c27b7f17249dbe2bb8353`, and `c127a85492758d155c03bcb7a2433626c933059a03a550653d0dd44bab1c704a`. The Linux benchmark compiles as a static RV64 ELF (SHA-256 `710b6322b338521b1e2d6f0cdf0f8d7ffb3bbdf4233f51cb47fb00cd8e86eec1`), but no FPGA fit or new physical Linux result exists for this diagnostic yet.
