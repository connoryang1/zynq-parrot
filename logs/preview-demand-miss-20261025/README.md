This directory preserves two physical Linux runs that count D-cache demand misses at the first target load after a scheduler preview hint. Both runs use the same diagnostic NBF and timing-clean preview RTL; the board was power-cycled, declared ready, and loaded with the verified overlay between runs. The counts test whether exact hints warm the target line before demand, while the cycle measurements test whether that local effect improves the whole handoff.

The routed package SHA-256 is `858cba88472432f157efab225baed74498f8740302fb5054dcd01aa93e42300b`; its bitstream SHA-256 is `5f1a725e215b7e46bc2c787df0b2820f536ec744b0ada4ada886483c942f2367`. The diagnostic source is on `experiment/linux-preview-demand-miss-diagnostic` at `55beb084`, with static benchmark SHA-256 `22e9b487b5637834ec4e725e1993c172d578358e384ff24c3ca9239438593766`. The 46 MiB Linux NBF SHA-256 is `b860ae3fd8594103b446fde75f683129bbbf2e21bbf86b6682375cc03a004b96`; its retained xz copy has SHA-256 `5291f76ae82eaf96510d060e1a2272ae13b3802d9897b548fb2553d0411f61e5`. The actual NBF is recoverable with `xz -dc linux-preview-miss.nbf.xz > linux-preview-miss.nbf`.

The benchmark uses 48 unique 64-byte target lines in one aligned page, 16 balanced off/exact/stale blocks, and ten pages of eviction before each handoff. CSR `0x805` counts accepted D-cache demand misses while excluding preview requests; the peer reads it immediately before and after the target load. Executable-section scans found no other uses of custom CSRs `0x800`–`0x807` in the rebuilt Linux kernel or OpenSBI `.text`. Both board runs printed `SCHED_PREVIEW PASS`, completed all 48 trials with armed recorder and no overflow, and returned `BSG PASS`/runner exit zero. Analyze each *raw guest log* with `python3 linux-tests/analyze_scheduler_preview_miss.py <guest-log>` from the source branch; the runner transcript repeats guest output and is not a valid analyzer input.

The first raw guest log SHA-256 is `f21861d27b162e99c445293dcb1d09d46bffd712b9b465bfb541c0ab331cb655`: off/exact/stale had 16/8/16 target demand misses. The repeat raw guest log SHA-256 is `97f6609f67d2f8bf451975372ec7c0b9db6f4da6ec25296c09dfb3a44e6d31ef`: the corresponding totals were 16/5/18, with exact eliminating the demand miss in 11 of 16 paired blocks and stale in none. The paired exact-minus-off median target load-after-entry changed by -63 and -7 cycles across the two runs. The paired exact-minus-off median *whole roundtrip* changed by -10,105.5 and +44.5 cycles, so there is no repeatable whole-switch speedup. These counts demonstrate useful target-line warming under the same-mm, exact-address workload; they do not establish request acceptance for every hint, cache response timing, or benefit for learned addresses or cross-mm tasks.
