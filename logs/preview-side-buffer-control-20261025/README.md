This directory records a directed simulator check of D-cache preview side-buffer retention under prior-entry pressure. It preserves the closed waveform and exact NBF for the new control and a previously known-good miss-recorder flow. The result addresses a specific capacity hypothesis; it does not explain the intermittent Linux trial or establish a workload speedup.

The first traced attempt compiled a five-slot model and the new test, but its 200,000-iteration publish poll produced no guest verdict during 104 ms of simulated target time. The run was interrupted after the simulator had advanced actively for roughly nine host minutes; its later host `BSG PASS` lacks the guest marker and is invalid. The minimal-example Makefile did not forward a native target-runtime argument. The guardrail now forwards `TARGET_RUNTIME_MS` through the testing harness to `+c_args`, following the existing black-parrot-example wrapper. The test poll was reduced to 4,096 iterations and emits phase markers. The interrupted waveform was not archived as a valid trace.

After a separate `make -C testing clean`, a clean traced model build used `NUM_THREADS=2 NUM_CONTEXTS=4`, `BP_DCACHE_PREFETCH_ELS=5`, `TRACE=1`, and `TMPDIR=/dev/shm/zp-preview-sidebuf-compiler-tmp`. The bounded command was `make -C testing run-mt_preview_side_buffer_pressure_test NUM_THREADS=2 NUM_CONTEXTS=4 TRACE=1 VERILATOR_BUILD_JOBS=8 TARGET_RUNTIME_MS=80`. It passed its specific guest marker, `CORE PASS`, and `BSG PASS` before the target limit. Four older hints published first, then four fresh target hints reached physical/admitted/issued/published counts `4/4/4/4`; all four target loads avoided accepted D-cache demand misses, while four separate cold off-control loads each missed. The test ELF, exact NBF, raw run log, and closed FST SHA-256 values are `0d884bbe31f7c6f4502c59250c891e4769c77c66ae5a78e4dd0de13e7cde2343`, `68727fd81cc95d34093a02f9defb5f66447d885714718f7e665218c84dff8fa4`, `c63979c19e9ef8bf76b08b9fb171b3409ced0f8091c67cf0f0a038a6ebfbb154`, and `838112633369a06e5101d470b896d65866496da3093e39a3bf54e0b7e7a1f0b3`.

The previously known-good `mt_cache_miss_trace_test` then ran serially under the same traced five-slot model and `TARGET_RUNTIME_MS=80`. It passed its specific guest marker, `CORE PASS`, and `BSG PASS`, reporting two I-cache and one D-cache accepted misses. The controlled result rules out a simple claim that four older entries necessarily displace four new target entries in a five-slot buffer. It does not cover Linux's translated scheduling path, other demand traffic, stores, L1 hits, multiple intervening schedules, or whether the four counted Linux publications held the intended addresses. Address-tagged buffer publication and removal evidence remains the next discriminator for RL-083's published-but-missed exact trial.
